# Threat Modelling 0.2.0 — release notes

Default icons, marks for untrusted zones and sensitive data, and one change to the language.

## Changed: the old .flow words are gone

`io`, `function`, `database` and `boundary`, the words of the DataFlow (`.flow`) format, were accepted as other names for `external`, `container`, `store` and `zone`. They no longer are: a model that uses one gets an error that names the word to write instead. To update a model, replace each one:

| Was | Write |
|---|---|
| `io` | `external` |
| `function` | `container` |
| `database` | `store` |
| `boundary` | `zone` |

## New

- **Default icons.** An element without an icon of its own gets one. A person is always `user`. Otherwise its `technology` decides when a word in it is known (React `globe`, Node.js `server`, PostgreSQL `database`, Kafka `list-ordered`, S3 `archive`, SMTP `mail`, Auth0 `key-round`, iOS `smartphone`), and then its kind (an external system `building-2`, a store `database`, a queue `list-ordered`). Systems, containers and components have no default; the [language reference](../language.md#icons) suggests some. `icon = "none"` leaves the icon off one element.
- **Untrusted zones** have a warning shield after their title in the Data flow view.
- **Sensitive data** (`#secret`, `#pii`, `#confidential`) has a padlock (🔒) on the flows in the Data flow view. The padlock is text, so it shows in copied diagrams too.
- The key under the Data flow view explains the shield and the padlock when the diagram has them.
- A **Default icons** setting turns off all of these at once (on to start with). Icons a model names are always drawn.

## Improved

- The table under each diagram is now called the **threat register**, as in the report: "Threat register (5)" when the view shows every threat, or "Threat register: 3 of 5 threats in this view".
- In Live Preview the bar above a model no longer sits under Obsidian's own button for editing the block.
- In saved reports, zones in the Data flow diagram are styled with a class rather than a style, so their title can carry the shield.
- The README has screenshots, and a tip on editing `.threat` files in VS Code.

## Requirements

Obsidian 1.15 or later. Works on desktop and mobile.

## Privacy

Unchanged: no network requests, and a file is written only when you ask.
