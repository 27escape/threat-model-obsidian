# Threat Modelling 0.3.0 — release notes

Change a model by clicking its diagram, now in Obsidian as well as in the web editor; zones on the Structure view; and a flow can go to an element that doesn't exist yet.

## New: editing from the diagram, in Obsidian

- **An *Edit* switch** in each diagram's bar (before *Report*). Turned on, the diagram gets an outline and the **Threat model editor** opens in the right sidebar. It starts off every time, so nothing changes your notes until you ask. Turning it on in another diagram moves the editor there; turning it off, closing the editor, or opening another file stops editing.
- **Click a box, a zone, an arrow or a threat** (its ID on the diagram, or its row in the threat register) to change it in the editor: a box's name, technology, zone, icon, link and description; a zone's trust; a flow's label, protocol, encryption, authentication and data; a threat's title, STRIDE categories, rating (likelihood × impact before and after its controls, a risk tag, or a CVSS vector), status, controls, owner, mitigation and description. Clicking a threat ID still shows its footprint too.
- **Add ▾ and Model ▾**, as in the web editor: add an element, a flow, a zone, a threat to the whole model, a control or a scenario; list the zones, controls, scenarios and problems. A box has *New flow from it* and, for a system or container, *New element inside*.
- **Delete** boxes, zones, flows, threats, controls and scenarios. A box takes its flows, and anything inside it, with it, after asking.
- **Undo and Redo** in the editor's bar, or Ctrl+Z and Ctrl+Shift+Z (⌘ on a Mac) while the editor is the active pane. In Live Preview and Source mode, Ctrl+Z in the note takes a change back too.
- **Problems:** the count in the editor's bar lists the errors, warnings and findings; each goes to its line in the note. ***Show in text*** selects the statement of what you clicked.
- **Open in the web editor** (a button in the editor's bar, and a command): opens the model in the web app in your browser. The model travels in the link after the `#`, which browsers never send to a website, so nothing is uploaded.
- **Your text is kept as you wrote it.** A change rewrites only what changed, inside the model's own code block, keeping comments, layout, a callout's `> ` or a list's indent, and Windows line ends. It is written only if the model's text is still what the editor read: if you typed in it meanwhile, nothing is written and you are told. In Live Preview and Source mode the change goes through the note's editor, as an ordinary edit; in Reading view it is written into the file. `.threat` files work the same way, with Undo and Redo in the file's bar.

## New: zones on the Structure view

Zones (trust boundaries) are drawn on the Structure view as dotted boxes, with the warning shield on an untrusted zone, as in the Data flow view. Because boxes are nested by what they are part of, and a zone can cut across that, zones are drawn within each level: at the top, and inside each system or container, the boxes in a zone other than the one around them are put in a zone box. So a system whose containers are in two zones shows both inside it. The *Zones* switch hides them, the key gains a *Zone* entry, and saved reports show them too.

## New in both the plugin and the web editor

- **A flow to a new element:** *New flow*'s *To* list ends with *A new element…*. Give its kind, name, parent and zone, and the element is added with the flow (one change, one Undo), then opened for you to fill in.
- **Deleting a box takes its flows with it**, instead of asking you to delete them first.
- The web editor opens links made by the plugin's *Open in the web editor*.

## Fixed

- A zone drawn inside another box lost its untrusted-zone shield (Pele draws a nested box's title elsewhere in the picture).

## Requirements

Obsidian 1.15 or later. Works on desktop and mobile.

## Privacy

Unchanged: the plugin makes no network requests. It writes to a note only when you save something in the Threat model editor (and then only inside that model's code block) or save a report. *Open in the web editor* opens your browser, only when you ask, with the model in the link's `#` part, which is never sent to the website.
